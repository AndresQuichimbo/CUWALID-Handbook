# Handbook Style Guide

## Voice and Tone

- Write as an official technical reference.
- Prefer clear, direct sentences.
- Explain scientific intent before technical steps.
- Avoid location-specific wording unless discussing case studies.

## Heading Hierarchy

- Use one H1 per file (chapter title).
- Use H2 for standard chapter sections.
- Use H3 only when needed for long sections.

## Box Conventions

Use these prefixes in bold at the start of a paragraph:

- **Note:** context or clarification.
- **Tip:** practical recommendation.
- **Warning:** risk or common failure mode.

## Code and Commands

- Keep code snippets short and purpose-driven.
- Explain each snippet using input, output, and rationale.
- Use fenced code blocks with language labels.

## Figures

- Every figure must have a unique identifier, title, and caption.
- Prefer vector outputs (SVG) for diagrams when possible.
- Keep color usage consistent with project palette.

## Tables

- Use concise headers.
- Include units for all scientific variables.
- Add source column for external datasets.

## Terminology

- Use DRYP and CUWALID terms consistently.
- Define terms in first use and in the glossary appendix.

## Chapter Completion Criteria

A chapter is complete when:

- All template sections are populated.
- Validation checklist is actionable.
- Figures and tables are referenced in text.
- Citations are included where scientific claims are made.
